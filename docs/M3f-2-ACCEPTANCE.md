# M3f.2 — geometry-checked spacing accents; exceptional-symbol diagnostics

## Evidence and limits
The user reports M3f.1 still displays standalone accent symbols in Citation. The supplied
rows have zero combining marks and zero neutralized inferred splits, but spacing accents.
Rows L5/L7/L9 each contain one rejectable glyph and zero unmapped glyphs. This narrows the
problem; it does NOT reveal the actual glyph or prove it is a Unicode bullet. The screenshot
is consistent with separate accent/base PDF glyphs. Native quads for that page were not
provided. M3f.1's exact 348-test runtime summary has not been supplied; no pass is invented.

## Changes
- Interpret adjacent spacing accent/base glyphs as an automatic quotation cluster ONLY if
  they have reliable Unicode, a unique adjacent Latin base, substantial horizontal overlap,
  close centers, compatible vertical alignment and a single canonical composed result.
  Both accent-before-base and base-before-accent source orders are supported.
- Acute, grave, circumflex, diaeresis, tilde and cedilla are a deliberately small mapping.
  ASCII caret/tilde/backtick require the SAME geometry, not ordinary text substitution.
- Ambiguous/conflicting/zero-width/unmapped/separate marks remain literal. No real space
  is consumed to search for a base. Quotation interpretation changes neither the copied
  glyph order/count, native quads nor raw visualText. Word and character endpoints keep
  accepted pairs whole; native selection geometry is still both real glyphs.
- Pair preparation is lazy per immutable row, linear in glyph count with two candidates
  per accent. Maps retain copied data only, never native handles. No measured latency,
  universal layout repair or device acceptance claim.
- The existing manual Diagnostic now shows at most eight exceptional samples per row:
  glyph offsets; control/replacement/joiner Unicode IDs; spacing-accent IDs and pairing
  status; normalized neighboring geometry if unpaired. Ordinary letters/numbers, full
  text, quotation, URI, document identity and native CID/GID numbers are never exported.
  Regional indicators are categorical, not their actual code points. Review the updated
  privacy notice before copying/sharing. No automatic clipboard/log/file/network action.
- Unknown bullet/control markers are NOT silently replaced, omitted or made selectable.
  Body-only selection behavior from M3f.1 remains. A range including a rejectable marker
  can still fail until its exact exceptional-symbol evidence supports a safe fix.

## Scope
No PDF writes, engine/dependency/SDK/wrapper/lock changes, toolbar changes, rendering,
retention-queue/native ownership/workspace changes or production annotation/history/save/
recovery/cross-column continuation. Manual Contents never use this interpretation.
Some real PDFs may have different font metrics, non-adjacent accent order or mappings;
those cases intentionally remain literal. Geometry is an inference, not semantic proof.

## Apply and validate
Extract the ZIP separately, preferably outside the project source tree.
Apply-M3f.2.ps1 -ProjectRoot ... -BuildAndInstall
-CheckOnly performs all preflight checks without changing the project.
The script requires the M3f.1 receipt generated by the previous supplied installer and
verifies all its recorded hashes, source test count 348, exact replacement anchors,
new-file collisions and unchanged build/native-safety files. It does NOT need a new
source export unless these guards detect drift. Backups precede writes; local apply
failure attempts byte-for-byte rollback. A later build/device failure leaves source
applied; retry Validate-M3f.2.ps1 -ProjectRoot ... -BuildAndInstall, not older repairs.
There are no automatic Git, uninstall, data-clear or SDK configuration operations.

Default ADB path is the user-provided SGPro path; -AdbPath can override it. -DeviceSerial
is required if more than one device is connected/authorized. BuildAndInstall builds,
reruns unit tests, Lints, checks actual JUnit XML, installs -r and runs the eleven existing
reader instrumentations. No new native suite is added; the old M1 synthetic annotation
mutation proof is not run. Expected count: 372 = M3f.1 348 + 24 new tests. Source declaration
counts and synthetic tests are NOT a successful runtime result.

## Tablet acceptance
1. Confirm M3f.2. Retest the SAME screenshot passage. Compare ingénierie, système, récente,
   émergeant, après, répondre, défis and complexité
   against the PDF. Verify ordinary spacing, punctuation and any genuine standalone marks.
2. Drag through a repaired word and adjust both handles within it. Accent/base must remain
   together, with no word cut at the standalone accent. Raw glyph geometry must stay aligned.
3. If an accent is still literal, open Diagnostic on that page and share a row's new
   "Accents associés / symboles exceptionnels" line. Unpaired examples include dx/h,
   dy/h and overlap/h for immediate neighbors, without exporting their ordinary text.
4. Repeat multi-item bullet selection. If it refuses, copy the report header and L5, L7,
   L9 INCLUDING their Unicode and exceptional-symbol lines. These are now known candidate
   rows from the supplied report; no full private PDF is needed.
5. Check literal quotes/backticks/caret/tilde, mapped bullets/list separators, existing NFC,
   decomposed accents, NBSP, handles/ellipsis, zoom/Fit/rotation retention, interrupted draft
   rollback, retained color on page navigation and cross-column refusal.

## Verification boundary
Host static source/patch replay, XML/resource consistency, test declaration counts,
package/ZIP hashes and independent geometry/Unicode reference checks are recorded in
validation.json. Kotlin/JUnit/Gradle/PowerShell/Android execution is unavailable here.
No compile, Lint, APK install, JNI success or exact real-PDF fix is claimed before testing.
